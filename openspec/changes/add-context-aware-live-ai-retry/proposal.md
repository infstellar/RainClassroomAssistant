# 添加带上下文的现场 AI 重试

## 为什么

当前现场 AI 兜底只分析当前题目页。部分雨课堂题目依赖前面 PPT 页面中的定义、数据表、假设或符号说明。遇到这类题时，模型可能已经看到了真实题目，但因为缺少上下文只能返回 `[]`，程序无法区分这是“没有题目”还是“有题但缺上下文”。

例如 “Express the contrasts for H01 and H02” 这一页，本页只有提问，H01 和 H02 的定义在前几页，因此单图分析无法得到答案。

## 改动内容

- 允许 AI 答案分析器返回专门的“上下文不足”标记。
- 现场兜底识别到该标记后，从同一个 PPT 中选择前置页面，按递增上下文窗口重试。
- 当前题目页始终作为目标页，前面的图片只作为上下文。
- 为每次重试、选中的页面范围、图片下载/复用、AI 返回和最终决策增加详细日志。
- 限制上下文扩展次数，避免 API 成本和等待时间失控。

## 建议重试策略

- 初始尝试：只给当前题目页。
- 上下文重试 1：共 3 张图。
- 上下文重试 2：共 5 张图。
- 上下文重试 3：共 7 张图。
- 上下文重试 4：共 9 张图。

最后一张图始终是目标题目页，前面的图片来自同一个 PPT 的前置页面。

## 非目标

- 不自动联网搜索公开资料来补充课堂上下文。
- 达到重试上限后仍然上下文不足时，不提交任何答案。
- 不改变雨课堂答题提交 payload 格式。
- 不替代现有人工答案覆盖机制。

## 风险

- 图片数量增加会提高 API 成本和响应时间。
- 前置页面可能包含无关例题或其他问题，干扰模型判断。
- 如果本地缓存页码和现场 PPT 数据页码不一致，必须依赖匹配后的 PPT 顺序选择上下文，否则可能选错页面。

## 待确认问题

- 重试次数和图片数量是否需要放入 `ai_analysis_settings`，还是先固定实现？
- 上下文重试是否只用于现场兜底，还是也扩展到离线批量分析？
