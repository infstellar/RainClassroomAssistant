## Why

批量 AI 预分析目前只分析单张题目页。若模型返回“上下文不足”，程序会把内部标记当作可用答案写入缓存，后续自动答题可能直接提交该标记。

现场 AI 兜底已经具备 3/5/7/9 张图的上下文重试能力；批量预分析应使用同样语义，在同一个 PPT 内补前置页面重试，而不是缓存无法提交的占位标记。

## What Changes

- 批量预分析遇到单图“上下文不足”时，按 3、5、7、9 张图递增上下文窗口重试。
- 上下文窗口只从当前 PPT 的 `slides_data` 中选择目标页之前的页面，最后一张始终是目标题页。
- 任一上下文重试返回可用答案时，将该答案写入缓存。
- 所有重试仍上下文不足、未识别到答案或 API 失败时，不缓存 `__INSUFFICIENT_CONTEXT__`，将该页视为失败页并生成手动填写模板。
- 读取缓存时过滤历史遗留的 `__INSUFFICIENT_CONTEXT__`，防止旧缓存被提交。

## Capabilities

### New Capabilities

- `ai-batch-analysis`: 批量 PPT AI 预分析的上下文重试、缓存写入和旧缓存过滤行为。

### Modified Capabilities

- 无。

## Impact

- 主要影响 [Scripts/AIAnswerAnalyzer.py](/d:/ProgramData/vscode/RainClassroomAssistant/Scripts/AIAnswerAnalyzer.py) 的批量分析流程和缓存读取逻辑。
- 需要增加针对批量上下文重试和旧缓存过滤的回归测试。
- 不改变现场兜底的答题提交逻辑，也不改变雨课堂 API payload 格式。

## 非目标

- 不扩展到跨 PPT、联网搜索或外部资料补充。
- 不改变现场兜底已有的 3/5/7/9 重试策略。
- 不把上下文窗口大小做成新的配置项，本次沿用固定策略。
- 不自动删除用户已有缓存文件，只在读取时过滤风险标记。

## 风险

- 批量预分析的 API 调用次数可能增加，尤其是多个题页都需要上下文时。
- 前置页面包含其他题目或干扰信息时，模型可能受影响，需要通过 prompt 和图片顺序约束降低风险。
- 如果某些 `slides_data` 项缺少对应本地图片，相关上下文窗口需要跳过或缩小，可能降低命中率。
